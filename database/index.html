Materials/API & agents

PROGRAMMATIC ACCESS

API & agents

Every record on this site is plain JSON with hash-anchored payload URLs. Scripts read it over HTTPS, and AI agents read it through a read-only MCP server. Neither path can change the archive: new data arrives as a pull request that CI validates and a maintainer reviews.

Read

MCP server

A stdio server that needs only the Python standard library and no credentials. It searches the catalog, opens records, returns SHA-256-verified file contents, parses band tables, and compares gaps.

Read

HTTP & JSON

Static JSON on GitHub Pages: a light catalog, one record per calculation, and payloads in the external archive with SHA-256 values and mirror URLs.

Write

Pull request

A contribution is a branch with one record, its evidence files, and regenerated indexes. CI runs the maintainers' gates; merging publishes the record and archives the bytes.

Install the MCP server and skills

In Claude Code, the repository is a plugin marketplace. One plugin installs the read-only MCP server together with two skills: one for reading data, one for contributing a calculation as a pull request.

/plugin marketplace add AroundPeking/LibRPA-database
/plugin install librpa-database@librpa

Any other MCP client (Claude Desktop, Cursor, Codex, and others) runs the same single-file server. It needs Python 3.9 or newer and works from a downloaded copy of plugin/mcp/server.py.

{
  "mcpServers": {
    "librpa-database": {
      "command": "python3",
      "args": ["/path/to/LibRPA-database/plugin/mcp/server.py"]
    }
  }
}

All paths are relative to https://aroundpeking.github.io/LibRPA-database/. Payloads in the external archive carry external_url, a mirror in external_url_backup, size_bytes, and sha256; verify the hash after downloading.

Contribute through a pull request

The database has no write API. Every new calculation goes through review, by a person or by an agent following the librpa-database-intake skill:

  1. Fork and branch. Create add/<case-id> in your fork of the repository.
  2. Add the record. Put record.json with inputs/, results/, logs/, and figures/ under data/calculations/<2d|3d>/<Material>/<case-id>/. Sanitize private paths first, then record each file's SHA-256.
  3. Regenerate, never hand-edit. Rebuild the catalog, the log index, and the evidence report with the repository scripts.
  4. Run the gates. Catalog and index checks, the public scan, and both test suites must pass locally.
  5. Open the pull request. The template asks for the candidate summary: source run, observable and scope, evidence, and limitations. CI runs Validate database on it.
  6. Review and merge. After a maintainer merges, Publish database deploys the site and External archive sync moves the payload bytes to the dataset archive. Contributors need no archive account.
